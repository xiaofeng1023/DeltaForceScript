# 三角洲市场流程升级方案（多页面状态机）

## Context

当前脚本只能做一件事：在**固定的抢购页面**上盯着 `time` 区域里的倒计时，剩 5 秒点刷新、≤1 秒点购买。游戏交易行的机制已经变了——现在需要先按赛季/品阶/成色筛选，再逐个浏览商品、把价格合适的加入「我的关注」，最后在关注页抢购。

用户提供了 9 张原生 2560×1440 截图并口述了完整操作流程，要求把脚本从"单页面倒计时抢购"升级为"多页面自动导航 + 关注筛选 + 抢购"。

本次升级后，脚本能自动完成：筛选 → 逐商品加关注 → 关注页抢购 → 关注清空后重新筛选，形成闭环循环。

**用户已确认的边界**：
- 起点是**用户手动**在游戏里打开「典藏外观」列表页（图三/图五）后，点脚本「开始」；脚本不负责从游戏大厅导航。
- 赛季名做成界面可配置项；品阶、成色同理。
- 在售商品网格**只处理当前页**，不翻页。
- 左侧商品列表**自动滚动到底**，处理全部商品。
- 抢购阶段**沿用现有倒计时逻辑**（剩 5 秒刷新、≤1 秒连点购买+确认），保留"获得外观结果页自动跳过"。
- 整体**无限循环**，新增「抢到 N 个后停止」参数（N=0 表示无限），替换原「任务完成后继续运行」复选框。

---

## 一、页面与流程状态机

主循环改为**页面驱动**：每轮截图 → OCR 特征文本识别当前页面 → 分派给对应 handler。相比"步骤驱动"，这样不怕漏点/多点/界面延迟，任意一页出错都能自愈回退。

### 页面标识

| 标识 | 界面 | 识别特征文本 |
| --- | --- | --- |
| `PAGE_BROWSE` | 典藏外观列表页（图3/5）：左侧商品列表 + 右侧详情 + 金色「购买」 | 「筛选」+「典藏工坊」或「当季产出」 |
| `PAGE_FILTER_DIALOG` | 筛选弹窗（图4） | 「品阶」+「枪种」 |
| `PAGE_SALE` | 在售列表页（图6/8） | 顶部「在售」，且**没有**「我的关注:」 |
| `PAGE_GRADE_PANEL` | 成色筛选侧栏（图7） | 「成色」+「重置」+「确定」 |
| `PAGE_FOLLOW` | 我的关注页（图9） | 「我的关注:」（正则 `我的关注[:：]\s*(\d+)\s*/\s*(\d+)`） |
| `PAGE_UNKNOWN` | 未识别 | 以上都不匹配 |

> 截图 6/8/9 布局几乎一致，唯一可靠区分是「我的关注: N/150」（图9 左下角）。`PAGE_FOLLOW` 优先判定，其次 `PAGE_SALE`。
> 实现时需用 OCR 实测确认图9 是否也有顶部「在售」页签；若有，仍以「我的关注:」为最高优先级。

### 主循环结构

```
while running:
    cfg  = get_config()                 # 每轮读取，GUI 改参数实时生效
    frame = capture()
    page = detect_page(frame)

    if stall_timeout_exceeded():        # 该页面卡太久
        recover_current_page(page)      # 按页面做不同恢复动作
        continue

    if phase == PHASE_SNIPE and page == PAGE_FOLLOW:
        sub = snipe_step(frame, cfg)    # 复用现有抢购逻辑
        if sub == 'empty':              # 关注清空
            phase = PHASE_PREPARE
            press_esc(); reset_prepare_context()
        continue

    phase = PHASE_PREPARE
    prepare_step(page, frame, cfg)      # 导航 + 加关注
```

### 必须持久化的上下文

| 变量 | 作用 |
| --- | --- |
| `phase` | `PHASE_PREPARE` / `PHASE_SNIPE` |
| `list_item_index` | BROWSE 左侧列表当前处理到第几项 |
| `list_scroll_bottom` | 左侧列表是否已滚到底 |
| `browse_filter_done` | 本轮 BROWSE 的筛选是否已提交（防止重复点「筛选」） |
| `grade_filter_done` | 当前 SALE 页成色筛选是否已提交 |
| `sale_cards_done` | 当前 SALE 页已处理过的卡片索引集合 |
| `bought_count` | 累计抢到数量（用于 `stop_after_count`） |
| `last_progress_time` | 通用防卡死计时（任何成功动作/页面切换都重置） |

**防重复机制**：每个 handler 执行动作前先检查对应的 `*_done` 标志；标志只在"页面切换"或"识别到结果变化"时重置（例如从 DIALOG 回到 BROWSE 时重置 `browse_filter_done`，从 SALE 回到 BROWSE 时重置 `sale_cards_done`）。

## 二、元素定位策略（目标是让用户尽量少标定）

本机是 2560×1440，与 `regions_2k.json` 基准一致，因此**默认坐标直接由截图 OCR 提取后写死**，用户无需交互标定即可跑通；`region_selector.py` 只作为非 2K 用户的**可选覆盖**手段。

| 元素 | 策略 |
| --- | --- |
| BROWSE 左上「筛选」 | OCR 文本锚点（顶部条区域找"筛选"），点文本中心 |
| 对话框「赛季」下拉框 | 固定区域（比例常量） |
| 赛季下拉**展开后**的选项 | 点下拉 → 截图 → 在"下拉框正下方"的扫描区域内 OCR，找到目标赛季文本后点其中心 |
| 「品阶」四个复选框 | 用 OCR 找到"品阶"这一行的 y 坐标，四个列的 x 用固定偏移 |
| 对话框「确认」按钮 | OCR 文本锚点找"确认" |
| BROWSE 左侧商品列表 | 固定大区域 + OCR 按 y 聚簇成行 → 每行中心为点击点；用鼠标滚轮向下滚动 |
| BROWSE 右侧「我的关注」入口 | OCR 文本锚点找"我的关注" |
| BROWSE 右下「购买」 | OCR 文本锚点找"购买" |
| SALE 左上「筛选」 | OCR 文本锚点找"筛选" |
| 商品卡片网格 | 固定区域 + 列数/行数常量等分，算出每张卡片矩形 |
| 卡片右下角价格 | 由卡片矩形推出右下角子区域，OCR 取数字 |
| ★关注星标 | 固定区域（右侧详情面板右上角），OCR 定位不可靠 |
| 成色侧栏选项（所有成色/S/A/B/C） | 固定区域 `grade_panel` 内 OCR 找对应单字符文本 |
| 侧栏「确定」 | OCR 文本锚点找"确定" |
| 底部「我的关注: N/150」 | 固定区域 OCR + 正则 |

**新增区域名**（写进 `regions_2k.json` 默认值，并加入 `region_selector.py` 的标定列表）：
`browse_filter`、`season_combo`、`season_options`、`tier_row`、`dialog_confirm`、`goods_list`、`detail_buy`、`my_follow_entry`、`sale_tab`、`sale_filter`、`goods_grid`、`grade_panel`、`grade_ok`、`follow_star`、`follow_count`

已有的 `time`、`buy`、`verify`、`refresh`、`money`、`skip`、`price`、`back` 全部保留给抢购阶段用。

## 三、文件组织（避免循环导入）

`gui_monitor.py` 不能 import `main_gui`（循环导入），现有约定是 `main_gui.py` 单向依赖其余模块。新代码沿用这个方向：

### 新建 `page_flow.py`
- 页面常量 `PAGE_*`、各元素的默认比例常量
- `detect_page(ops, selector, frame) -> str`
- `class MarketFlow`，构造签名：

```python
MarketFlow(ops, selector, get_config, notify)
```

`ops` 是一个**接口对象**（由 `ScriptThread` 自己传入 `self`），需要提供：
`capture()`、`ocr_region(region, frame=None)`、`ocr_region_boxes(region, frame=None)`、`click_region(region)`、`click_point(pt)`。

这五件事 `ScriptThread` 里已经有 3 个（`ocr_region`/`ocr_region_boxes`/`win_cap.capture`），只需再补两个薄封装方法（内部调用模块级的 `click_region_center` / `click_point`，注意方法名与模块级函数重名，方法用 `click_region` / `click_point_at` 区分）。

`MarketFlow` 暴露：
- `prepare_step(page, frame, cfg) -> str`（返回 `'running'` / `'to_snipe'`）
- `reset_prepare_context()`

依赖方向：`main_gui.py → page_flow.py`，**反向不依赖**，`page_flow.py` 也不 import `main_gui`。

### 改 `main_gui.py`
- `ScriptThread` 补两个点击薄封装方法
- 把现有 `run()` 的抢购循环抽成 `_snipe_step(frame, cfg) -> str`（返回 `'continue'` / `'empty'` / `'unknown'`），**逻辑一行不改**，只把"顶层 while"让出去
- `run()` 改为上面的两阶段主循环
- `_recover_ui()` 改为接收当前页面参数，按页面做不同恢复动作

## 四、GUI 新增配置项（`gui_monitor.py`）

| 控件 | 类型 | 取值 | 默认 | `get_config()` 键 |
| --- | --- | --- | --- | --- |
| 目标赛季 | `QComboBox(editable=True)` | 预置常见赛季名，允许手输 | 疾光魅影 | `target_season` |
| 目标品阶 | `QComboBox` | 传说品阶 / 史诗品阶 / 稀有品阶 / 普通品阶 | 史诗品阶 | `target_tier` |
| 目标成色 | `QComboBox` | 所有成色 / S / A / B / C | A | `target_grade` |

- 排布：新控件插在「价格上限」与底部复选框之间，沿用现有 `QHBoxLayout` + `setFixedWidth(120)` 的标签写法。
- 每个新控件配一个 `on_xxx_changed` 回调 + `add_log`，保持与现有回调命名一致。

## 五、风险点与兜底

| 风险 | 兜底 |
| --- | --- |
| 赛季下拉展开后选项位置不确定 | 点击下拉后重新截图，在"下拉框正下方矩形"内 OCR 找目标文本；找不到则该轮跳过，等下一轮重试；连续失败 3 次则告警并停止准备阶段 |
| 点击后页面没刷新完就继续操作 | 每次点击后 `time.sleep(0.6~0.8)`；关键跳转（点「购买」进 SALE）后等待并重新截图确认页面变了 |
| OCR 读错价格 | 价格读取失败按"不关注"处理（宁可漏，不可错关注）；识别到的数字超出合理范围（如 <10 或 >999999）同样丢弃 |
| 左侧列表项数量动态变化、滚动到底判断 | 滚轮前后各 OCR 一次列表区域文本，若文本集合不再变化则判定到底；同时设最大滚动次数上限（如 10 次） |
| 点击左侧商品后右侧详情未切换 | 点击后点「购买」前，先 OCR 右侧标题区域，确认标题变化再继续 |
| ESC 在游戏里可能打开菜单而非返回 | 统一用 `pydirectinput.press('esc')`；若连续 2 次未回到 `PAGE_BROWSE`，则改用 `back` 区域点击；两条路都失败则告警并暂停线程 |
| 多页面下原防卡死逻辑误触发 | 原"倒计时停滞 5 秒"判断**只在 `PAGE_FOLLOW` 生效**；其他页面用"页面停留时间超时"判断（阈值单独常量，如 25 秒） |
| 页面识别误判导致死循环 | 每个 handler 维护自己的重试计数；同一动作连续失败超过阈值 → 强制 `ESC` 回 `PAGE_BROWSE` 并重置本轮上下文 |
| 关注数量上限（150） | 每次点星标前读 `follow_count`，达到上限则跳过加关注、直接进入抢购阶段并告警 |
| `stop_after_count` 达到时正在关注页 | 计数在 `_buy_and_check` 判定扣款成功后累加；达到 N 则 emit `task_completed` 并停止线程 |

## 六、实施顺序

1. **提取坐标**：写一个一次性只读脚本，用本地 PaddleOCR 对 9 张截图逐张识别，输出所有 UI 文本及其原生坐标；据此确定第二节所有元素的默认坐标。
2. **新建 `page_flow.py`**：先实现 `detect_page`，再逐个实现 handler（`handle_filter_dialog`、`handle_browse`、`handle_sale`、`handle_grade_panel`、`handle_follow`）。每个动作都打 `notify` 日志便于实机定位问题。
3. **改 `main_gui.py`**：抽 `_snipe_step`（保持原逻辑不变）→ 改造 `run()` 为两阶段循环 → 补点击封装方法 → `_recover_ui` 按页面恢复。
4. **改 `gui_monitor.py`**：新增 4 个控件 + 回调 + `get_config()` 键，移除旧复选框。
5. **改 `region_selector.py` + `regions_2k.json`**：区域名列表扩展，写入默认坐标。
6. **回归**：`python -m py_compile` 四个文件；启动 GUI 用「👁 预览」核对每个区域框是否套准 UI 元素。
7. **实机分阶段验证**（见下）。
8. 更新 `使用说明.md` 并重新打包（用户此前已要求过打包分发）。

## 七、验证方式

- **静态**：`python -m py_compile main_gui.py page_flow.py gui_monitor.py region_selector.py`（现有项目一直用这个方式验证）
- **区域核对**：启动 `main_gui.py`，点「👁 预览」，逐个人工确认框选位置（预览会把所有区域画框并标注名称，见 `main_gui.py` 的 `on_preview`）
- **实机分阶段**：
  1. 手动进入游戏「典藏外观」列表页 → 点「开始」→ 观察日志是否停在"筛选对话框"并把赛季/品阶设置正确（可先用「确认」前的日志判断）
  2. 观察左侧列表是否逐个商品走完、在售页价格读取是否正确、星标是否点中
  3. 观察「我的关注」页抢购是否复用成功、结果页是否自动跳过
  4. 关注清空后是否自动回到列表页重新开始
- 每个阶段的日志都会带中文动作描述（沿用现有 `status_updated.emit` 直接显示到 GUI 日志区的做法），便于实机排查。
