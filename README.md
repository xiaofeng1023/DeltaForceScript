# DeltaForceScript

> 基于 **PyQt6 + DXGI (dxcam) + PaddleOCR 3.x + 原生 Win32 SendInput** 的《三角洲行动》交易行自动筛选关注与毫秒级视觉闭环抢购工具。  
> 项目原型参考自 [BugNotFoundX/DeltaForceScript](https://github.com/BugNotFoundX/DeltaForceScript)，在此基础上重构了多页面全自动状态机与毫秒级闭环抢购引擎。

---

## ✨ 核心特性

### 1. 毫秒级视觉闭环抢购引擎
针对交易行 1 秒级抢购窗口进行了全链路延迟剥离：
- **1ms 系统时钟 + 4ms 帧级捕获**：自动开启 `timeBeginPeriod(1)` 高精度定时器与 `precise_sleep`（睡眠误差 `< 0.2ms`）；`WindowCapture` 区分静止帧与新帧，彻底消除桌面静止时的轮询休眠空窗，支持 DXGI 丢失自动重连。
- **亚秒级跳秒相位锁定（Tick Phase Lock）**：利用轻量灰度像素差分（`~0.3ms`）代替逐帧重型 OCR，精确记录倒计时每次跳秒的 `perf_counter` 相位，并在 **5 秒刷新回包后强制权威 OCR 重同步**，杜绝刷新换榜首商品导致的秒数错算。
- **`2~4 秒` 提前预审与鼠标预悬停**：在倒计时 `2~4s` 空闲期提前完成榜首商品价格上限校验（主价格区 + 列表首卡兜底单次批量识别）并缓存结果；`<= 3s` 时提前将光标移至「购买」按钮上方悬停，预先激活 Unreal Engine (Slate UI) 控件 Hover 焦点，使 **1 秒开火瞬间达到 0 次 OCR、0ms 移鼠延迟**。
- **原生 Win32 极速点击 + 视觉闭环切入确认**：
  - 绕过 `pydirectinput` 冗余查询，直调 64 位对齐的 `user32.SendInput`，附带 `8ms` 微帧级按压保持，彻底解决 UE4/UE5 同帧 0ms 点击吞首击问题。
  - 持续高频探测「购买」（在预计归零区间自动加密至 `25ms/次`），同时以 `< 0.3ms` 局部抓帧实时监测确认按钮区域像素突变；**一旦确认弹窗出现，`< 8ms` 内立即中断购买连击、瞬间切入 `30ms/次` 极速「确认」连击**，弹窗闭合后补 1 下保险即停。
- **智能无损善后（无缝连抢）**：单次批量识别 `跳过 / 关注数 / 三角币余额`；若弹窗已自动闭合且画面仍在「我的关注」页，**绝不乱按 `ESC`**（避免把自己踢出关注页浪费 5~8 秒），善后耗时压缩至 `~0.35s`，支持多件临期商品连续抢购。

### 2. 全自动多页面准备与防卡死返航
- **全流程自动加关注**：自动完成「赛季 + 品阶」筛选 → 逐商品进入在售列表 → 按「成色」筛选 → 逐屏 **6 张卡片单次批量 OCR 预读价格** → 达标商品自动点亮 `★` 加关注（自动识别星标颜色与复选框勾选态，防止重复点击取消）。
- **滚动错位自适应 & 超价即停**：在售列表按价格升序排列，读到超上限价格立即按 `ESC` 返回换下一个商品；整屏达标则自动向下滚到底，滚动后发生网格错位时自动按价格实际纵坐标反推卡片中心精准点击。
- **关注页自动排序与临期避让**：进入「我的关注」页自动将排序切为「按稀有度升序」（已匹配则跳过）；若刚进页时商品倒计时 `<= 7s` 即将开抢，自动推迟排序检查，优先保住眼前商品。
- **多级看门狗与大厅返航链**：结果页弹出「获得外观」自动点「跳过」；意外退回时支持从 **游戏大厅 → 交易行 → 典藏外观列表 → 我的关注** 全自动寻路返航；连续恢复无效自动停机保护。

### 3. 灵活运行模式与挂机守护
- **起点自适应**：停在「典藏外观」列表页启动则执行完整「筛选 → 加关注 → 抢购」循环；停在「我的关注」页启动则直接进入抢购阶段。
- **仅在我的关注页抢购模式**：勾选后完全跳过筛选与加关注，只盯抢手动挑好的关注列表（不套用价格上限，抢空后原地静默等待手动补货）。
- **挂机策略与配置持久化**：支持「抢到 N 个后自动停止」与「市场关闭时段（默认 `05:00 ~ 08:00`）自动停机」；所有界面参数改动实时生效并自动保存至 `user_config.json`。

```text
  │           ├── 单次批量预读本屏 6 张卡片价格（错位自动扩大采样并反推卡片中心）
  │           ├── 价格 <= 上限 ──► 检测星标未亮则点 ★ 加入关注（本屏全达标则向下滚继续扫）
  │           └── 价格 >  上限 ──► 立即按 ESC 返回列表页处理下一件商品
  └── 列表扫描完毕 ──► 点击右侧「我的关注」进入抢购阶段
        └── [我的关注页 · 毫秒级闭环抢购]
              ├── 安全窗口(>7s)校验并切换排序为「按稀有度升序」
              ├── t <= 5s  : 点击「刷新」，回包后强制权威 OCR 重同步新榜首倒计时
              ├── t = 2~4s : 提前预审缓存榜首价格 + 光标预悬停至「购买」按钮

              ├── 智能善后 : 自动点掉「获得外观 · 跳过」/ 保持留在关注页 ──► 核验三角币扣款
              └── 关注列表抢空(0/150) ──► 退出关注页回到列表页开启下一轮循环
```

## 🚀 快速开始

### 环境要求
- **操作系统**：Windows 10 / 11（64 位）
- **Python 版本**：**Python 3.11**（推荐实测版本 `3.11.9`，安装时勾选 `Add python.exe to PATH`）
- **运行权限**：**管理员权限**（游戏窗口内鼠标/键盘模拟必需，`start.bat` 与 `main_gui.py` 均会自动请求提权）
- **显卡支持**：推荐 NVIDIA 显卡 + 对应 CUDA 驱动（走 GPU 推理最快；无 N 卡可回退 CPU 版）
- **分辨率**：内置 `regions_2k.json` 适配 **2560×1440 (2K)**；其他分辨率运行一次 `region_selector.py` 标定即可

### 方式一：双击 `start.bat` 一键启动（推荐）
直接双击项目根目录下的 `start.bat`，脚本会自动完成：
1. 请求 UAC 管理员权限；
2. 检测并创建 `.venv` 虚拟环境；
3. 自动向 `.venv` 安装 `requirement.txt` 依赖（网络波动自动切换清华源重试）；
4. 从 Paddle 官方源安装 `paddlepaddle-gpu==3.4.0`；
5. 启动 GUI 监控窗口。

### 方式二：手动命令行安装与运行
> ⚠️ 请务必使用 `.venv\Scripts\python.exe -m pip` 安装，避免误装进系统全局 Python。

```powershell
# 1. 创建虚拟环境并安装基础依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirement.txt

# 2. 安装 GPU 版 PaddlePaddle（3.x 未发布在 PyPI，需指定 Paddle 官方源）
#    cu129 / cu130 源最高版本为 3.4.0；若为 cu118 / cu126 驱动请改为 paddlepaddle-gpu==3.3.1
.\.venv\Scripts\python.exe -m pip uninstall -y paddlepaddle
.\.venv\Scripts\python.exe -m pip install paddlepaddle-gpu==3.4.0 --extra-index-url https://www.paddlepaddle.org.cn/packages/stable/cu129/

# [可选] 若无 NVIDIA 显卡，改裝 CPU 版：
# .\.venv\Scripts\python.exe -m pip uninstall -y paddlepaddle-gpu
# .\.venv\Scripts\python.exe -m pip install paddlepaddle==3.4.0 --extra-index-url https://www.paddlepaddle.org.cn/packages/stable/cpu/

# 3. 验证 GPU 是否可用（可选）
.\.venv\Scripts\python.exe -c "import paddle; paddle.utils.run_check()"

# 4. 启动主程序
.\.venv\Scripts\python.exe main_gui.py
```

### 方式三：打包单文件便携版 EXE（免装 Python 分发）
在已配好 `.venv` 的开发机上执行：
```powershell
powershell -ExecutionPolicy Bypass -File build_exe.ps1
```
产物位于 `dist\DeltaForceScript.exe`（内置便携版 Python 3.11.9，首次在目标机运行时自动部署依赖，后续更新 exe 会自动同步最新脚本代码并保留用户的 `regions_2k.json` 与 `user_config.json`）。

### 准备离线 OCR 模型（推荐，启动更快且免联网下载）
将检测与识别模型放入 `models/` 目录下（未放置时首次启动会自动联网下载）：
- 检测模型（[ModelScope 下载](https://modelscope.cn/models/PaddlePaddle/PP-OCRv5_server_det)）：`models/PaddlePaddle--PP-OCRv5_server_det/snapshots/master/`
- 识别模型（[ModelScope 下载](https://modelscope.cn/models/PaddlePaddle/PP-OCRv5_server_rec)）：`models/PaddlePaddle--PP-OCRv5_server_rec/snapshots/master/`

确保两个目录内均包含 `inference.json` 与 `inference.pdiparams`。

## 🎯 区域标定（RegionSelector）

- **2560×1440 (2K) 显示器**：内置 `regions_2k.json` 已完成实机标定，直接点击界面右下角 **「👁 预览」** 核对无误即可开跑。
- **其他分辨率（如 1080P / 4K / 带鱼屏）**：运行标定工具按提示框选保存：

```powershell
# 依次标定区域（不需要重标的直接按 ESC 跳过，自动合并保留已有配置）
.\.venv\Scripts\python.exe region_selector.py

# 单独标定「需要先手动点开」的下拉面板（按回车后延迟 8 秒截屏，期间切回游戏点开下拉框）
.\.venv\Scripts\python.exe region_selector.py season_options follow_sort_options --delay 8
```

> **核心必准区域提示**：
> - `time`（倒计时文本）、`buy`（购买按钮）、`verify`（确认弹窗里的确认按钮）、`follow_count`（左下角 `我的关注：N/150`）。
> - 其中 **`verify` 区域同时承担视觉闭环弹窗检测职责**，请确保框在确认弹窗的「确认」按钮本体上。
> - 启动后监控窗口会自动停靠在主屏右侧（避开左下角 `follow_count` 等识别区），请勿将其拖到游戏画面左侧。

## ⚙️ 界面参数与实战调优说明

所有参数在运行中修改**立即生效**，并自动持久化到 `user_config.json`：

| 参数项 | 默认值 | 作用说明与调优建议 |
| :--- | :--- | :--- |
| **购买点击延迟** | `0.00 秒` | 进入 `<= 1秒` 窗口后首次点击前的等待。闭环模式下保持 `0.00` 零延迟即可 |
| **确认点击延迟** | `0.00 秒` | 检出确认弹窗到开始点确认之间的额外等待，保持 `0.00` 最快响应 |
| **购买点击间隔** | `0.05 秒` | 高频探测「购买」按钮间隔（预计归零区间会自动加密至 `0.025s`；弹窗一出立即停止点购买） |
| **确认点击间隔** | `0.03 秒` | 确认弹窗弹出后的极速连点间隔（`30ms/次`） |
| **购买点击次数** | `24 次` | 最大探测点击次数（`24 × 0.05s` 完整覆盖跨秒解锁窗口；检出弹窗会立即提前结束） |
| **确认点击次数** | `20 次` | 最大确认点击次数（检测到弹窗闭合后会自动补 1 下保险并提前结束） |
| **OCR间隔(t>5s)** | `0.50 秒` | 倒计时 `> 12s` 时的轮询间隔（`5~12s` 自动提速至 `0.08s`，`<= 5s` 自动切入 `4ms` 帧级追踪） |
| **价格上限** | `230 三角币` | 超过该价格不加关注、不购买（抢购阶段在 `t = 2~4s` 提前完成预审缓存） |
| **目标赛季** | `王者之剑` | 可下拉选择内置 12 个赛季，也可直接在输入框手填新赛季名称（精确匹配优先） |
| **目标品阶 / 成色** | `史诗品阶` / `A` | 准备阶段自动勾选对应的品阶与在售成色筛选条件 |
| **抢到后停止** | `不限 (0)` | 累计检测到扣款抢到指定件数后自动停止脚本 |
| **市场关闭时段** | `05:00 ~ 08:00` | 处于每日休市区间内脚本自动停机（填成相同时间可禁用） |
| **剩余5秒时点击刷新** | `开启` | 倒计时 `<= 5s` 时刷新一次关注列表，重排最新临期商品并重同步倒计时 |
| **仅在我的关注页抢购** | `关闭` | 开启后跳过筛选与加关注，仅抢当前关注列表已有商品（不限制价格上限） |

### 📊 如何看懂毫秒级抢购战报日志？
每次出手后，界面与 `logs/YYYY-MM-DD.log` 会输出形如以下诊断信息：
```text
⚡ 抢购连击完成(238ms | 跳秒+4ms | 买×3[108ms检出弹窗] → 确认×4, 弹窗闭合即停)
```
- **`跳秒+4ms`**：倒计时跳入最后窗口后仅隔 `4ms` 即发出第 1 击。
- **`买×3[108ms检出弹窗]`**：第 3 下购买点击成功打开了确认弹窗，并在 `108ms` 被视觉闭环捕获，立即中断后续多余购买点击。
- **`确认×4, 弹窗闭合即停`**：极速点下 4 次确认后检测到弹窗已提交关闭，提前结束空点并留在关注页继续蹲守下一件。
- 若频繁出现 **`[未检出弹窗变化(兜底点击)]`**，请点击「👁 预览」检查 `buy` 与 `verify` 区域坐标是否与当前游戏分辨率一致。
